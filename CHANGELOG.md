# Agent Hub release notes

## 2.0.3 — Доставка событий релиза в активный ход

- `Автор`: `IIITYRAELIII` (GitHub UID `95281881`).
- `Компоненты`: `agent-hub`.
- `Для кого`: пользователи и операторы Agent Hub.
- `Действие`: `recommended`; обновить установленный Hub для своевременной доставки событий выпуска.
- `Контракты`: `REL-001`, `MCP-001`, `MSG-001`, `PERF-001`.
- [HUB-325](agent-hub://task/660a7f8f-8121-4efa-9144-c13e9d36cc72 "Доставлять события релиза в ход"): события выпуска передаются в активный ход штатным steer; при отсутствии активного хода действует обычная доставка в Stream. Существующие payload, частота, представление, история и исходные идентификаторы событий сохранены. Существующий CommandTrace получает раздельные этапы создания, приёма и provider delivery; реальная MCP composition подключена к тому же recorder.
- `Проверка`: точный результат принят независимым ревьюером после исправления подключения trace; адресные producer/root проверки и обычные Test/Await прошли. Полный набор тестов пропущен по согласованному исключению; пропуск не означает PASS. Фактическая доставка новым установленным runtime в активный provider turn проверяется отдельно после штатной установки.
- `Установка/обновление`: использовать установщик, ZIP, дескриптор и SHA256SUMS из одного GitHub Release; см. `AgentHub/distribution/INSTALL.md`. Конфигурация и данные сохраняются.
- `Перезапуск`: перед ручным обновлением штатно остановить Hub; после установки выполнить штатный запуск. Управляемое переключение выполняет существующий владелец установки и безопасного перезапуска.

## 2.0.2 — Самостоятельная поставка Agent Hub

- `Автор`: `IIITYRAELIII` (GitHub UID `95281881`).
- `Компоненты`: `agent-hub`.
- `Для кого`: пользователи и разработчики Agent Hub.
- `Действие`: `recommended`; использовать самостоятельный репозиторий и установочные файлы одного GitHub Release.
- `Контракты`: `REL-001`, `RST-001`, `UPD-001`.
- [HUB-329](agent-hub://task/16343338-b3be-4703-82fb-0fd4ee1598e6 "Вынести Hub в отдельный репозиторий"): отдельный публичный репозиторий с сохранённой проверенной историей; Windows ZIP, установщик и контрольные суммы формируются из неизменяемого runtime штатного выпуска. CI отдельно проверяет исходники; native-проверка runtime и упаковщик используют единый список файлов наблюдателя релиза. Установка сохраняет конфигурацию и данные, отказывает при изменении принадлежащих выпуску файлов и поддерживает возврат к сохранённому предыдущему runtime.
- `Проверка`: адресные проверки исправлений и ручная установка/обновление/отказ при локальной правке/повтор/откат проверены в изолированных каталогах. Полный набор тестов пропущен по выбору владельца; пропуск не означает PASS. Публичное скачивание, приёмка конкретного нового архива и managed-переход подтверждаются отдельно после публикации.
- `Установка/обновление`: использовать `install_release.py`, `AgentHub-win32-x64.zip`, его дескриптор и `SHA256SUMS` из одного GitHub Release; см. `AgentHub/distribution/INSTALL.md`. Node.js и Python требуются; Git, npm и компилятор для установки не нужны. Установщику явно указывается каталог runtime.
- `Перезапуск`: перед ручным обновлением штатно остановить Hub; установщик не останавливает и не запускает его автоматически. После установки выполнить штатный запуск.

  регистрация первой публичной исходной точки. Неопределённый результат загрузки
  сохраняется до проверки внешнего эффекта. Опубликованная версия и история
  учитываются при обычном Test/Await без зависимости от удалённого каталога сборки.
  Эти изменения не объявляют архив опубликованным или установленным.
- `Проверка`: выполнены необходимые адресные проверки; полный набор пропущен
  по выбору владельца. Пропущенные проверки не считаются успешными.
- `Установка/обновление`: используйте архив, `install_release.py` и контрольные
  суммы одного GitHub Release; см. `AgentHub/distribution/INSTALL.md`.
- `Перезапуск`: установщик не запускает Hub; после установки применяется
  штатный запуск, после обновления — согласованное окно остановленных writers.

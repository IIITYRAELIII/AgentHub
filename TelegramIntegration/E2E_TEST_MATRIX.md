# Матрица CLI-приёмки TelegramIntegration

`npm run test:e2e` запускает настоящий `bot.mjs` в изолированном временном каталоге. Вместо внешних сервисов используются локальные HTTP Telegram Bot API, Codex App Server и Claude CLI из `e2e`. Рабочие токены, `config.json`, пользовательские треды, папка `data` и производственные логи не читаются и не изменяются.

## Покрытые сценарии

| Область | Проверка |
|---|---|
| Запуск | первичное создание Codex-треда, `/start`, сохранение `state.json` |
| Каталог задач | `/tasks`, порядок кнопок, новая задача перед архивированием |
| Локальная синхронизация | сохранение каталога, истории, статуса, `turnId` и владельца `VSCode App Server`/`Integration App Server`/`Codex Desktop App`/`Codex CLI`/неизвестного external; ограничение кэша без вытеснения активных задач; фоновое observer-подключение реального внешнего fake-хода без самопроизвольной progress-карточки; показ по запросу; протухание фантомного running; отсутствие записи неизменившихся poll-снимков |
| Выбор | переход на другую задачу, повторный выбор текущей, восстановление `threadId` |
| Настройки задачи | модель Codex, reasoning, Plan/Work, закреплённое название |
| Обычный ход | запуск, progress, токены, diff, финальный ответ, очистка active run; владелец Telegram-run остаётся `Integration App Server` после фонового poll и восстановления состояния |
| Подтверждения | запрос команды и одноразовое UUID-разрешение, привязанное к точному Telegram-сообщению; legacy-счётчики не принимаются; безопасная MCP-форма автоматически принимается в авто-режиме без лишнего сообщения пользователю |
| Конфликт сообщений | запрет второго turn в занятом thread, указание владельца App Server, `Показать текущий ход`, `Отменить`, `Поставить в очередь`, `Отправить в новую задачу` |
| Параллельность | два одновременно активных хода, переключение между ними обоими типами кнопки с глазами, независимая отмена и восстановление обоих ходов после рестарта процесса |
| Очередь | запуск сохранённого сообщения после завершения/отмены занятого хода |
| Архив | запрет при активном ходе, успешная архивация после завершения и отказ устаревшей кнопке меню воздействовать на позднее выбранную задачу |
| Просмотр | новые кнопки используют единый `show-message`; старый `show-last-message` совместим и тоже подключает live-ход, а без активного хода показывается последний ответ |
| История | `Показать ещё` перестраивает представление с последовательным увеличением числа пар `1 → 2 → 3` |
| Отмена | `/cancel` относится только к выбранной задаче; неудачный interrupt внешнего хода сохраняет observer и блокировку второго turn |
| Доставка | HTTP 500, outbox, повторная отправка progress и финала; групповой порядок частей, вытеснение старого progress, конкурентная append-only запись и безопасная компактация bindings; сбой `getUpdates`, ограниченный backoff и последующее восстановление polling |
| Состояние Windows | повтор атомарной записи при `EPERM`/`EACCES`/`EBUSY` |
| Codex recovery | падение App Server во время хода, переподключение и доставка восстановленного финала; откат незавершённого turn и безопасное продолжение после потерянного MCP-запроса в авто-режиме |
| Рестарт | системный single-instance lock, восстановление активного run и фактического владельца после процесса, штатный `/restart` с сохранением Telegram offset и обновлением карточки; соседний update из уже полученного пакета обрабатывается новой копией ровно один раз; временная ошибка `thread/resume` не создаёт новый выбранный тред поверх сохранённого активного хода |
| Нагрузка | управляемый Telegram-ход использует поток App Server и не вызывает частый `thread/read`; чтение истории и live-снимка одного треда объединяется; короткий внешний VSCode-ход, целиком прошедший между опросами, всё равно доставляет финал по новому `turnId` |
| Медиа | медленная загрузка изображения не блокирует команды и переключение; начатый после загрузки ход остаётся привязан к исходной задаче, модели и режиму; два быстрых изображения проходят FIFO-очередь ровно по одному разу; принятая работа сохраняется до Telegram offset, переживает жёсткое завершение бота во время загрузки, завершается после старта новой копии и очищает журнал |
| Статус | отправка медиа-карточки `/status` |
| Агенты | переключение Codex → Claude → Codex и полноценный ход fake Claude CLI |
| Проекты | переключение между двумя разрешёнными проектами с отдельными контекстами |

## Матрица параллельности Claude

`bot.claude.e2e.test.mjs` запускает отдельный экземпляр бота с `provider: "claude"`, подставным Claude CLI и изолированным домашним каталогом, поэтому реальные сессии `~/.claude/projects` не читаются.

| Область | Проверка |
|---|---|
| Параллельность | две одновременно активные задачи Claude с разными сессиями и собственными файлами вывода |
| Конфликт сообщений | занятая задача Claude предлагает отложенное сообщение и запуск в новой задаче |
| Выбор и просмотр | `/tasks` показывает обе живые задачи, переключение и `Показать сообщение` не останавливают ни одну |
| Отмена | `/cancel` завершает только выбранную задачу Claude и останавливает настоящий дочерний процесс CLI; незавершённый transcript отменённого управляемого хода не воскресает как внешний observer |
| Рестарт | процесс CLI переживает жёсткое завершение бота и штатный `/restart`, ход подключается заново и доставляет финальный ответ; сообщение о прерывании не отправляется, а `/restart` не откладывается |
| Фантомная активность | брошенный незавершённый transcript выбирается как задача, но не блокирует новый ход |
| Гонки наблюдения | переключение задачи или запуск управляемого хода во время чтения snapshot не создают observer для прежнего thread/session |
| Уборка | осиротевшие `data/claude-runs/*` удаляются при старте, файлы восстановленных активных ходов сохраняются |

## Команды

```powershell
npm run check
npm test
npm run test:e2e
npm run test:all
```

`npm run check` одним процессом разбирает все `.mjs` без исполнения. `npm test` — быстрые unit/integration-тесты. `npm run test:e2e` — процессная CLI-приёмка. `npm run test:all` последовательно выполняет синтаксическую проверку, оба набора тестов и является основной командой перед выпуском.

В `npm test` также входит изолированная приёмка control plane: публикация двух runtime-релизов, атомарное переключение и откат `current/previous`, отсечение тестов и локальных секретов из release, явная миграция config/data, ожидание завершения активных ходов перед cutover и локальный IPC, разрешающий только отправку сообщений и изображений без передачи Telegram-токена.

## Границы

Headless-стенд проверяет протоколы, состояние и маршрутизацию без управления компьютером. Он не оценивает визуальный рендеринг карточек конкретной версией мобильного/настольного Telegram, качество распознавания речи и звучание TTS. Формирование соответствующих Bot API-запросов покрыто модульными тестами; визуальная оценка остаётся отдельным необязательным smoke-тестом.

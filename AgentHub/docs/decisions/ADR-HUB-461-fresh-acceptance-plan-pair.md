# Fresh acceptance plan pair

Status: proposed

The existing preflight independently resolved current and prospective Await plans
at every validation boundary. In one measured twenty-result admission twelve
serial full scans occupied 365.8 seconds of a 546.4-second server workflow.

The existing planner now supplies an internal acceptance pair. Each boundary
resolves live evidence for the union once and computes both original plans with
the same domain function. Evidence is never reused by another boundary, retry,
request or process. Public plan arguments and result shapes remain unchanged.

After Git work the planner rereads canonical Task rows and all durable selected
composition/closure authority. It compares the release-relevant identities,
retaining freshness that the old two independent calls supplied. Unrelated
metadata on earlier Tasks does not invalidate release identity; the accepting
Task retains its exact row revision. Identity-only snapshots cannot replace proof.

All four promotion boundaries, final lifecycle CAS, history/content checks,
publication/base/source/claim guards, leases, rollback and UNKNOWN behavior stay
with their existing owners. Existing payload-free timing measures canonical
reads, selected authority, live Git and pure projection separately. There is no
new public API, writer, cache, selector or deadline. Deterministic counts and real
end-to-end measurements must establish the actual improvement.

Fresh validation also propagates a blocked current plan instead of treating an
unchanged revision hash as successful live Git evidence. The normal public plan
still reports blocked results; preflight refuses them at the existing boundary.
The new fixed diagnostic classes remain separately aggregated after the existing
detailed-span bound is reached. No diagnostic bound or sink is replaced.

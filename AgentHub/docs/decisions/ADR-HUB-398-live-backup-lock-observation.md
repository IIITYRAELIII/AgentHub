# ADR-HUB-398: live backup support and owned lock directories

The retained public update failed before stopping: live support enumeration
listed a native lock ready directory, then lstat observed its absence. The
historical removal schedule is not recorded. The deterministic regression
joins actual native publication/release between those same production I/O
boundaries, without changing durable data or retrying an update.

Live preflight uses the existing interprocess lock producer's call-scoped
read-only observation. Exact locally created directory identity, and an already
admitted publication/removal's confirmed outcome, distinguish its ephemeral
paths. Names, UUID appearance, ages and foreign owner files are not authority.
An absent observed entry joins only that already-running producer outcome;
unknown effect, replacement, durable-file disappearance and unowned lookalikes
still refuse. The observer performs no mutation, lock acquisition, retry,
timer, cleanup or durable bookkeeping. Records live only while their actual
producer or an inspection holds them. Other-process lock churn is not inferred.

The observer re-reads the exact path after joining a pending producer reply.
Only fresh absence plus confirmed original removal permits exclusion. A new
directory, regular file or link refuses even if created before that reply
settles. Removal bookkeeping shares the exact promise awaited by the release
owner, so an unexpected I/O rejection retains its original diagnostic without
creating a detached rejection or confirming removal. Maintained tests hold the
actual native reply across replacement and exercise the existing EIO effect
port without an unhandled-rejection suppression listener.

All live intake/pre-stop callers use this support entry point. It does not
grant snapshot/stop authority. The stopped inventory, identity equality,
custody/reparse/config/SQLite checks and exclusive output/copy/hash/integrity
work remain strict and fresh after original retirement.

## Historical terminal original

The existing failed maintenance original is terminal. Neither an unchanged
restart-package request nor its retained bootstrap can resume it. Both return
the saved result; the domain transition rejects terminal regression. Runtime
adoption alone cannot recapture the old original's binding, and a failed row
with an ENOENT message does not prove native admission never happened.

An explicit `resume-package` command now admits a next attempt in the existing
maintenance row, under its runtime restart mutation queue and SQLite CAS. It
requires the same five-key business input, exact failed revision/binding and
fresh current release/PID/pointer/manifest/instance hashes. The controller must
have positively recorded that this attempt failed in package backup preflight
before entering stopping. Error text, an absent native receipt or a historical
failed row cannot supply that evidence. UNKNOWN and admitted native/backup/
launch effects refuse. The original controller invocation must drain first.

The same original preserves each complete failed attempt and binding in
`packageAttemptHistory`; only its active attempt projection advances. The
generic terminal transition remains forbidden. Fresh preparation validates
public bytes/selection, physical roots, actual current instance and launcher.
A competing active restart refuses. Existing notification, blocking work,
stopping, native retirement, stopped backup and one-launch owners remain intact.

The retained bootstrap can produce an explicit `resume-input` document from a
fresh readonly original/current observation. The caller retains that exact
document for `resume`. Its normalized hash is the addressed request identity;
saved duplicate readback precedes preparation and returns the original without
another launch, including after a lost reply or process reopen. A changed CAS,
input, assets, physical root or current refuses. No terminal row, receipt or
historical cache is deleted/reset, and no second operation ID or ledger exists.
The historical production original lacks typed pre-stop evidence and remains
readback-only. Adoption of this correction does not authorize its revival.

# ADR-0117: Verify installed source and adopted incoming independently

The authorized release combines already installed local repairs with one exact
conditionally accepted external origin. A single origin=OWN-publication test
cannot express both facts. Comparing every Task's final metadata with its old
registered base also mistakes inherited published notes/version for Task edits.
Neither issue permits dropping integrity checks or overlaying runtime files.

Extend the existing installed-local-source envelope with a paired exact approved
origin and selected adoption pins. Reuse the ordinary Task adoption Git records,
prove their canonical blobs, current refs and bounded merge objects read-only,
and retain the complete installed source/tree/patch/manifest/physical-byte proof.
The candidate still starts from the verified installed source and uses native
Git selected merges. Source and external identity stay separate. A later Task
snapshot needs its own ordinary adoption record; a later origin is not followed.

Native history may exclude only independently verified installed/adopted
ancestry. Metadata must be identical to registered-base/installed/adopted
metadata, including mode for CHANGELOG. Task-authored notes/version remain
release-owned and must be removed by an ordinary source correction, with their
old Git history retained. No blanket metadata waiver is introduced.

Test uses the same proof, storing it in its existing native integration intent
and repeating it before effect and terminal checks. Its managed dev prefix is
preview context only and grants no publication membership. Candidate promotion,
prepared reuse, generation and freeze independently repeat the current receipts,
origin, source and installed pins. Existing rollback, CAS, process guards and
same-original unknown recovery remain authoritative. All owned Git calls remain
sequential within the existing single process-tree guard scope.

There is no new adoption writer, public approval boolean, installed-file overlay
or incoming bootstrap. The existing reviewed local owner delivery exception may
deliver this mechanism before ordinary Task adoption/Test/Await and canonical
publication. That bootstrap is not the product release. After supported main
synchronization contains the installed repairs, the one-time local migration
envelope is unnecessary; ordinary adoption authority remains explicit.

# Retained original runtime allocation recovery

The existing public continue owner may recover an unchanged retained frozen
generation after a later compose positively failed because its own prepared
runtime occupies the original immutable build number. Allocating another build
or attributing that artifact to another generation would change the admitted
publication identity.

This route is restricted to an idle failed compose, complete positive failed
future receipts, an existing applied compose/validation and terminal not-applied
publication receipts. The exact current all-Await membership, selected results,
NONE selection, complete frozen test plan, notes, authorization and versions
must equal the retained generation. Existing RM authentication and request/CAS
arguments remain authoritative. Other terminal failures retain their existing
continuation policy.

The existing generation owner verifies its retained identity, clone, manifest,
checkpoint, frozen metadata and clean source. The existing installation lease
protects prepared runtime inspection and the recovery CAS. The publication
owner verifies its recorded executor, joined failed runner, pre-effect journal,
artifact identity, manifest, full payload and original prepared receipt. The
runtime must remain outside current, previous, running and retirement custody.
Every target requires a fresh positive not-applied readback. Changed, partial,
unknown or foreign evidence refuses.

The release store repeats receipt and immutable-generation checks inside its
existing SQLite transition transaction. Recovery is an append-only original-ID
event and record. The old failed generation/compose/publication receipts remain
unchanged. A fresh publication attempt uses the SAME frozen generation through
the existing publisher and fingerprints. It creates no new compose/freeze or
allocation and preserves completed checkpoints. Exact request replay reads the
saved admission without scheduling another run.

This pre-release correction does not implement the broader deferred retry and
performance work. Pending validation still follows the exact frozen selection.
The current explicit NONE exception does not certify the interrupted full suite
or change publication/build/health requirements. Existing original trace spans
measure retained-generation verification separately from publication work.

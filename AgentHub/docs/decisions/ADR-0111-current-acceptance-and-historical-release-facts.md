# ADR-0111 — Current acceptance and historical release facts

Status: accepted by explicit user scope, 2026-10-14; execution evidence remains separate.

The release path incorrectly compared a new reviewed correction to historical
selected results and added special successor/recovery approvals to preserve that
equality. This caused real terminal composition failures even with the same eleven
Tasks and one normally accepted corrected result. Task capability also incorrectly
closed publication-source admission. Ownership denial spun background scheduling;
dev conflict blocked exact delivery; optional archive parsing broke startup.

Remove these historical selection/state dependencies. Current normal acceptance,
preparation and reservation bind each new immutable candidate. Retain historical
original/generation/authorization/version/entry/effects readback for its factual
purpose, including OWN published ancestry and foreign-origin protection. Ordinary
retry reconciles actual effects before a new operation; it never revives terminal
history or replays UNKNOWN. Existing owner and SQL/lease fences remain authoritative.

Verified exact Task delivery is separate from pending dev synchronization and
service completion. Archive errors remain entry diagnostics, not startup authority.
Denied acquire does not immediately reschedule; temporary ownership retains normal
bounded retry/wake. Task capability is not a publication veto. No additional owner,
ledger, allow flag, migration framework or manual release permission is introduced.

The direct production hotfix is explicitly user-authorized; hotfix install/health
and the main release's publication/readiness/completion are separate observed facts.
Unchanged accepted checks carry. New affected checks verify ordinary corrected
preparation/reservation, foreign/unaccepted refusals, ownership scheduling, exact
Task completion, and actual artifact boot with malformed archive + native fence.

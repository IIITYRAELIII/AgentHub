# Retained source repositories and original combined previews

An ordinary claim can prepare the current standalone repository while preserving
an older managed checkout. A later successful Test replaces the canonical result
references and retains the previous references in its lifecycle outcome. Treating
every preserved checkout as a current contribution wrongly requires a survivor
Test result in the old repository. Removing that coverage check for every missing
reference would instead hide unknown work and break ordinary multi-repo closure.

The existing Task store supplies a bounded read of its successful claim binding,
baseline, canonical claim result and committed Test outcome. Only an exact
single-current-repository replacement yields retained references. The current
result, managed path, prior reference set, Task and Workspace identities must
agree. The existing Git owner still locks and inspects every managed repository.
A retained checkout must match the prior branch, HEAD and owner result ref and
remain clean with existing process and withdrawal guards. Unproved extra roots
take the original coverage refusal. All ordinary multi-repository results retain
the complete survivor Test and content checks.

Historical repositories are separate preservation evidence in the existing
combined preview. No OID is reinterpreted across repositories. Their complete
folders, ignored work, branches, objects and history stay in place; they cannot
enter squash cleanup. The owner rereads the same evidence after prospective
composition, and confirmation recomputes the full token. This compatibility
classification can disappear when no such retained repository replacements remain;
it is not a migration writer or an automatic repository-retirement policy.

The existing cleanup receipt owner also admits an explicit SAME ordinary
combined-closure read-only preview whose canonical receipt is UNKNOWN. Immutable
protocol-v1 arguments/hash, exact original actor, no cancellation and no lifecycle
intent/outcome are required. The owner takes its normal Await, both Task and
repository leases and proves the fresh complete current composition. Its existing
receipt transaction repeats both Task revisions, source authority and whole old
receipt before retaining that whole UNKNOWN inside previewRecovery and saving the
new preview. A refusal preserves the old receipt. This branch uses no diagnostic
error-string inference and grants no general NO_EFFECT or mutation replay.

An ordinary get remains read-only; a lost acknowledgement reads the stored same
original. Actual closure is a separate confirmation with that fresh exact token.
Unknown confirmations, special modes, foreign/changed actors or arguments and
already admitted lifecycle work remain excluded. No new tool, schema, queue,
writer, source transfer or release membership change is introduced.

An ordinary positive return preserves the accepted source result and can leave
its earlier dev integration reachable. The existing canonical returned-result
reader binds that return to the committed source Test, exact current result and
branch, original dev integration and both immutable outcome hashes. The ordinary
absorption owner may use that boundary only while the source is returned, with
no later successful Test after the return. The existing selected-content reader
checks all of the source work against the exact tested survivor; source ancestry
alone supplies no content credit. Every separate integration must be contained
in the returned Test dev boundary. Both the Git proof and the canonical return
are read again after prospective composition and in the preview receipt CAS.
Missing, foreign, stale, still-active or changed authority keeps refusal. This is
not a fabricated native handoff, a second return, a dev rollback or a change to
ordinary Test's multiple-merge-base policy.

Prospective composition uses the existing repository/object owner for its
invocation-only scratch location. System TEMP can be on another volume and
cannot host consumers of physically identical hardlinked native objects.
Both fresh composition and prepared verification therefore create their unique
temporary root in that owner's data storage, retaining existing process/lease
ownership and finally cleanup. Immutable object-link checks, prepared candidates,
checkpoints and primary repositories keep their existing boundaries; no copy
fallback, global environment rewrite or new materialization owner is added.

The real composer also requires authority for the ordinary transfer merge side.
An old ordinary Test has no native absorption descriptor. Retrofitting one would
invent an authenticated handoff and require different lifecycle results. The
existing canonical selected-composition read therefore also projects distinct
ordinary absorption history, only for the same executor's successful public
claim, exact normal source return and survivor Test. This internal closure
context comes from held Git evidence and the current public complete original,
not new public arguments. It binds the exact merge, source parent/tree, baseline,
metadata, references, linked work and immutable authority hashes. Git's unchanged
selected-content reader checks all earlier and newer source work first.

Release planning hashes and transports that history through the real prospective
composer. Native history validation permits only the bound ordered merge side;
other unselected merges and non-linear source ancestry still refuse. At SAME
preview CAS and both existing archive transaction boundaries the canonical
authority is read again. The completed lifecycle absorbedInto outcome retains
the proof, so the survivor's later ordinary Await and manifest readback use the
same authority instead of failing after successful closure. The canonical archive
increments the source revision exactly once; any further source mutation or
reopen invalidates that history. Later tested survivor descendants retain the
original merge proof without acquiring authority for another side.

The primary regression uses guarded production stores and public claim/Test/
normal-return, ordinary merge/survivor Test, SAME UNKNOWN preview, the real
planner/preflight/Git composer, fresh token, separate confirmation and subsequent
ordinary Await/readback. The prospective-composition port is not replaced.
Foreign side, missing earlier/new work, newer source and late canonical authority
mutation are negative cases. Earlier partial composer-port tests retain their
limited attribution; neither they nor this owner correction change the separate
multiple-base ordinary Test policy or settle its UNKNOWN original.

An invocation-only data directory previously hid canonical accepted native
resolutions, then removed the checkout named by a new conflict. Fresh validation
now routes only native captures to the existing repository owner's layout. Its
existing release-Git lock is acquired inside ordinary preparation, preserving
repository-owner/lock ordering. The canonical prepared checkpoint/manifest reader
supplies the existing legacy-prefix binding; ordinary implementation/context and
exact-stage verification still decide reuse. The isolated clone, checkpoint and
promotion stay invocation-local and are cleaned normally. Issued native conflicts
remain in their existing journal namespace after the finite invocation releases
its leases. Normal resolution commits and the same preview continue there; later
ordinary acceptance verifies the same capture. No extra resolver, registry, copy,
native policy exception or reconstruction of a deleted live checkout is added.

A shorter current-context capture must not suppress lookup of the separately
bound canonical legacy prefix. The existing reader may offer that prefix beside
current candidates, then the sequencer verifies every exact step and selects its
longest verified prefix. Historical journal bytes and their implementation stamp
remain unchanged. Different implementation hints still require current exact
conflict stages and clean-context verification rather than prefix adoption.

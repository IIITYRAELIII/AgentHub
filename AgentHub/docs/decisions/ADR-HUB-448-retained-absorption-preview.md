# Retained source repositories and original combined previews

An ordinary claim can prepare the current standalone repository while preserving
an older managed checkout. A later successful Test replaces the canonical result
references and retains the previous references in its lifecycle outcome. Treating
every preserved checkout as a current contribution wrongly requires a survivor
Test result in the old repository. Removing that coverage check for every missing
reference would instead hide unknown work and break ordinary multi-repo closure.

The existing Task store supplies a bounded read of its successful claim binding,
baseline, canonical claim result and committed Test outcome. Only an exact
single-current-repository replacement yields retained references. The current
result, managed path, prior reference set, Task and Workspace identities must
agree. The existing Git owner still locks and inspects every managed repository.
A retained checkout must match the prior branch, HEAD and owner result ref and
remain clean with existing process and withdrawal guards. Unproved extra roots
take the original coverage refusal. All ordinary multi-repository results retain
the complete survivor Test and content checks.

Historical repositories are separate preservation evidence in the existing
combined preview. No OID is reinterpreted across repositories. Their complete
folders, ignored work, branches, objects and history stay in place; they cannot
enter squash cleanup. The owner rereads the same evidence after prospective
composition, and confirmation recomputes the full token. This compatibility
classification can disappear when no such retained repository replacements remain;
it is not a migration writer or an automatic repository-retirement policy.

The existing cleanup receipt owner also admits an explicit SAME ordinary
combined-closure read-only preview whose canonical receipt is UNKNOWN. Immutable
protocol-v1 arguments/hash, exact original actor, no cancellation and no lifecycle
intent/outcome are required. The owner takes its normal Await, both Task and
repository leases and proves the fresh complete current composition. Its existing
receipt transaction repeats both Task revisions, source authority and whole old
receipt before retaining that whole UNKNOWN inside previewRecovery and saving the
new preview. A refusal preserves the old receipt. This branch uses no diagnostic
error-string inference and grants no general NO_EFFECT or mutation replay.

An ordinary get remains read-only; a lost acknowledgement reads the stored same
original. Actual closure is a separate confirmation with that fresh exact token.
Unknown confirmations, special modes, foreign/changed actors or arguments and
already admitted lifecycle work remain excluded. No new tool, schema, queue,
writer, source transfer or release membership change is introduced.

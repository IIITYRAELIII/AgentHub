# ADR-HUB-372 — Verify and reuse unchanged native computation

## Cause and decision

Every complete plan identity previously created a fresh native staging checkout.
A corrected tail therefore repeated unchanged merges and previously resolved
conflicts. The user approved fixing this on 2026-10-29. The existing native
sequencer remains the only state/effect owner; this changes ordinary preparation,
not Task Test integration, publication selection or the release command.

Each new plan keeps its own full identity and journal. Sibling captures are hints,
not authority. The full normalized ordered Task entries, repository/common dir,
Workspace, base, policy, provenance/history authority and current implementation
hash must match. Reuse stops at the first changed entry. Git bundle transport
imports the verified prefix; it does not copy an old final candidate containing
an excluded tail. The current verifier checks each step without old review fields.
Within one invocation, the same immutable proof is not computed three times;
after restart it is re-established. Final whole-current selected content/history,
runtime import closure and the owning fresh authority/lease/CAS remain mandatory.

## Repeated conflict

Only exact whole conflict stage/path/mode/blob context qualifies. Starting with
the actual new Git automatic tree, Git object operations substitute retained
regular-file conflict entries and create a two-parent commit with the NEW parents.
The current marker/context verifier must accept it without a review capability.
New automatic contributions elsewhere remain unchanged. If the old afterimage
needs outside-marker authority or context changed, the ordinary conflict/fresh
review remains. Deletion/type/other unsupported afterimages take that ordinary
path; arbitrary binary merges gain no authority. This is bounded resolution
reuse, not resurrection of a synthetic selected-content projector.

Old review envelopes, compatibility exemptions and bindings are never relabelled
with a new identity. The new journal stores transport intent before object import
and checkout intent before abort/checkout. Actual Git readback recovers lost replies.
Foreign dirty or ignored bytes are preserved; no forced cleanup/reset is used.
Old captures/journals/receipts are not edited. Reuse creates no external admission,
new ledger, writer, staging registry, timeout, skip gate or retry policy.

## Rollout bridge and removal condition

Pre-upgrade captures have no implementation context. Arbitrary unstamped siblings
are ignored. One exact existing prepared checkpoint can be a seed through its
existing owner: manifest digest, root/common-dir/ref, Workspace, base/provenance,
full journal identity/merges/head/tree and raw hashes must agree. Fresh history
authority and complete old native verification run in the new private Git objects
under the old identity. Each reused prefix step then passes current verification
without old review. Source checkpoint/manifest/journal hashes are re-read at use.
Current ref/authority/dirty failures are not disguised as successful reuse.

No old record is retroactively stamped. After matching post-upgrade captures
exist, ordinary current-context reuse takes precedence; the bridge is no longer
needed for those captures. It remains only while a current prepared checkpoint
can still refer to a supported pre-upgrade implementation.

## Evidence and application

Real Git regressions cover corrected last/middle entries, removal/order/full-entry
drift, base/provenance drift, forged hints, races, lost checkout/abort replies,
foreign bytes and changed conflict stages. A separate controlled review-port
oracle proves an old outside-marker v1 review cannot authorize a new identity;
it is not production receipt authentication. Actual preparation checks the legacy
seed and runtime import-closure refusal before promotion. Existing original-ID
timing reports lookup/transport/verify/remaining work/final checks. Merge-call
reduction alone is not an end-to-end Await speedup claim; compare like fixtures.

This source result does not apply itself to a running release or add itself to
its selected product set. A compatible reviewed source execution context must
preserve all current owners and runtime source membership, then use the existing
public lifecycle/CLI. Missing runtime JSON is a separate correction. No installed
runtime patch, live publication or immutable historical identity rewrite follows
from accepting this implementation.

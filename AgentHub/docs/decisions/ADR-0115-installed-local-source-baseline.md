# ADR-0115: Bind an installed local source baseline to one release

Status: accepted scope; implementation requires exact affected review and delivery.

The current incident has a published Git baseline, older agreed local main and
later authorized local repairs already installed. Starting a release from that
older main would discard repairs. An installed-file overlay would leave Git
unable to describe execution. The user clarified that local repairs and their
one-time Git migration need no additional GO; external incoming remains separate.

Use one discriminated immutable provenance envelope in the existing preparation,
candidate, generation, freeze and preflight owners. It binds the actual installed
manifest and source reconstruction to the exact selected results. Verification
checks current OWN origin/publication, unchanged primary, source tree/patch and
installed runtime bytes, including original compiled Host inputs and the actual
bounded regular Host executable against its required manifest record. Only the
four supported Host build inputs use compiled provenance; unknown Host sources
refuse migration. Retained text EOL and Git LFS representations are explicit;
unproved executable bytes refuse.

The source base is merged with exact selected Task results using native Git.
Conflicts and necessary compatibility changes use the existing isolated checkout
and independently authenticated native review. The existing preparation owner
classifies a private pre-promotion merge conflict as a definite
refusal and retains the issued resolution checkout, rather than leaving a
non-resumable preparation receipt unknown. Preparation rechecks under its
existing leases before promotion; freeze independently repeats the pins before
ref CAS. The current primary stays attached and untouched. One original receipt
and expected-old rollback own unknown outcomes. A sealed candidate can be reused
only with unchanged complete provenance and selected identity.

Delivery first installs the reviewed owner correction by the already authorized
immutable repair mechanism, preserving the previous generation. Then ordinary
Task Await/preparation/run consumes it, freezes the calendar version and release
notes, builds from Git and verifies actual production. Source-ready is not
delivery. This does not add other product Tasks to the selected release.

The boundary retires naturally after publication and supported main sync contain
the reconstructed source. It does not authorize future local bases implicitly,
new external commits, a permanent runtime overlay or a second release engine.

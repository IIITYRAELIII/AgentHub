# Аудит безопасности Agent Hub

Дата: 2026-08-02. Область: локальный Hub, VS Code/Desktop, Telegram Mini App,
прямой HTTPS-шлюз и Android-клиент. Это аудит персонального однопользовательского
развёртывания, не многопользовательского интернет-сервиса.

## Итог

Критических и высоких уязвимостей в проверенном контуре не обнаружено. Публичные
данные и команды защищены Telegram initData либо сессией доверенного Android-
устройства; локальный Web-интерфейс использует отдельную HttpOnly-сессию. Один
практический риск отказа в обслуживании устранён в ходе аудита. Остаётся один
низкий принятый риск внешнего JavaScript Telegram.

## Исправлено

### SEC-001 — Medium — неограниченные запросы публичной авторизации

- Расположение: `mini-app-server.mjs:401`, `mini-app-server.mjs:471`,
  `mini-app-server.mjs:710`; `direct-gateway.mjs:105`.
- Свидетельство: endpoints сопряжения принимали ограниченное по размеру тело, но
  не имели частотного лимита; Node.js использовал длительные стандартные сетевые
  таймауты.
- Влияние: внешний клиент мог создавать лишнюю криптографическую и сетевую
  нагрузку, не зная кода сопряжения.
- Исправление: 30 попыток в минуту на адрес клиента, `429 + Retry-After`, таймаут
  заголовков 15 секунд, запроса 30 секунд, ограничение keep-alive и числа
  запросов на соединение. Caddy теперь сам задаёт `X-Forwarded-For`, удаляет
  недоверенный `CF-Connecting-IP` и запрещает встраивание через `X-Frame-Options:
  DENY`.
- Дополнительное ограничение: 20-символьный случайный код сопряжения хранится
  только как SHA-256 и действует десять минут.
- Ложное срабатывание: не применимо; отсутствие лимита подтверждалось маршрутом
  и отдельным тестом, новый лимит проверяется 31-м запросом одного клиента.

## Принятый низкий риск

### SEC-002 — Low — официальный Telegram Web App JavaScript

- Расположение: `mini-app-server.mjs:240`, CSP `script-src`.
- Свидетельство: CSP разрешает скрипт с `https://telegram.org`, необходимый Mini
  App. Сторонний JavaScript исполняется с полномочиями страницы.
- Влияние: компрометация официальной раздачи Telegram затронет Telegram Mini App.
- Ограничение риска: разрешён один точный источник, остальные скрипты
  same-origin; `connect-src` ограничен текущим origin, данные API требуют свежую
  подписанную Telegram initData. Для прямого Android-клиента этот скрипт не даёт
  дополнительных полномочий устройства.
- Исправление: не применяется, пока официальный Telegram Mini App требует этот
  runtime; удаление источника сломает Telegram-контур.
- Ложное срабатывание: риск относится только к странице, которая реально
  загружает официальный runtime Telegram; локальные клиенты используют ту же CSP,
  но не получают Telegram-полномочий без подписанной initData.

## Подтверждённые меры

- Android использует P-256 ключ из Android Keystore; challenge одноразовый и
  живёт две минуты, сессия — 12 часов, отзыв устройства удаляет его сессии.
  Проверено в `trusted-device-store.mjs:7-9` и `trusted-device-store.mjs:195`.
- В хранилище записываются SHA-256 хэши кодов сопряжения и токенов сессий, не
  исходные секреты.
- Android запрещает cleartext, смешанный контент, доступ WebView к файлам и
  игнорирование ошибок TLS; запросы WebView ограничены HTTPS origin Hub.
  Проверено в `AndroidManifest.xml:13` и `MainActivity.java:206-240`.
- API журнала, истории, вложений, событий и управления проходят авторизацию;
  публичными остаются статические ресурсы и `/health`.
- CSP запрещает inline/eval, формы, объекты, base URI и фреймы; пользовательский
  запрос и ответ экранируются перед проекцией в HTML журнала.
  Проверено в `mini-app-server.mjs:227-244` и `work-log-usage.mjs:351-353`.
- Runtime-каталоги и секреты на Windows ограничиваются ACL текущего пользователя,
  SYSTEM и Administrators; исходные токены не попадают в Git.
- `npm audit --omit=dev` не обнаружил уязвимостей производственных зависимостей.

## Граница гарантии

Безопасность Hub не защищает открытый RDP-порт, учётную запись Windows,
скомпрометированный телефон или процесс с правами текущего пользователя. Текущий
Hub рассчитан на одного владельца и не обеспечивает изоляцию нескольких
недоверяющих друг другу пользователей.

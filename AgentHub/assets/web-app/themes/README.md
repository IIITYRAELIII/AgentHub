# Пакеты тем Agent Hub

Одна тема — одна папка `themes/<id>`. Для добавления темы не нужно менять
`index.html`, `app.js`, сервер, Cloudflare Worker или расширение VS Code: все три
среды сканируют этот каталог через общий `theme-registry.cjs`.

## Минимальная тема

Создайте папку, например `themes/aurora`:

```text
aurora/
├── theme.json
├── theme.css
└── aurora.webp
```

`theme.json`:

```json
{
  "id": "aurora",
  "name": "Аврора",
  "color": "#08131f",
  "order": 140,
  "styles": "theme.css",
  "backgrounds": [
    { "id": "aurora", "name": "Аврора", "asset": "aurora.webp" }
  ]
}
```

`theme.css`:

```css
html[data-theme="aurora"] {
  --bg: #08131f;
  --accent: #70e0cf;
}

html[data-theme="aurora"] body::after {
  background: linear-gradient(90deg, rgb(3 8 14 / 65%), transparent), url("./aurora.webp") center / cover;
}
```

После этого тема автоматически появится в `Настройки → Тема`, её CSS и ресурсы
будут раздаваться по `/themes/aurora/...`, Worker включит папку в публикацию, а
VS Code webview преобразует те же пути в разрешённые локальные URI.

## Поля `theme.json`

- `id` — обязательный внутренний id: строчные латинские буквы, цифры и дефисы;
  имя папки должно в точности совпадать с `id`.
- `name` — название в списке тем.
- `color` — шестизначный цвет `#rrggbb` для `theme-color` WebView.
- `order` — уникальное целое число, определяющее позицию темы в списке.
- `styles` — CSS-файл или массив файлов. Если поле отсутствует, используется
  `theme.css`.
- `shellLayout` — контракт desktop-композиции: `shared` по умолчанию сохраняет
  общую геометрию Hub; `custom` разрешает теме владеть компоновкой защищённых
  shell-компонентов. Используйте `custom` только для целиком согласованной
  авторской композиции, которую нельзя выразить общими `--shell-*` токенами.
- `scripts` — необязательный JS-файл или массив файлов; скрипты подключаются с
  `defer` после общего `app.js`.
- `markup` — необязательный HTML-файл или массив файлов. Содержимое вставляется
  в общий слой `.theme-atmosphere`; так тема может добавить canvas или другие
  декоративные узлы, не меняя `index.html`.
- `aliases` — необязательные прежние id темы для восстановления сохранённого
  пользовательского выбора.
- `assets` — необязательная карта именованных файлов для CSS-токенов, которые
  используются общими стилями Hub. Например, `"iron-frame": "frame.png"`
  создаёт точный URL в `--<id>-iron-frame-asset`; это одинаково работает в
  браузере, Worker и VS Code webview.
- `backgrounds` — непустой массив сцен темы. Первая сцена обязана иметь тот же
  `id`, что и тема, и считается сценой по умолчанию.

Поля сцены:

- `id`, `name` — внутренний id и подпись в списке `Фон`;
- `asset` — необязательный файл изображения в этой же папке;
- `preload: true` — сначала загрузить и декодировать тяжёлый кадр, затем
  переключить видимую сцену;
- `particles` — один из встроенных слоёв `rain`, `downpour` или `motes`.

Если встроенного слоя недостаточно, добавьте собственные `scripts` и `markup`.
Скрипт должен сам проверять активный `document.documentElement.dataset.theme`,
учитывать `prefers-reduced-motion` и останавливать дорогую работу при скрытии
страницы. Примеры с canvas находятся в `metropolis` и `stormglass`.

## Ресурсы и ограничения

- Храните всё специфичное для темы внутри её папки: CSS, JS, HTML и изображения.
- Фирменный знак принадлежит общей оболочке и намеренно остаётся одинаковым во
  всех темах и поверхностях. Пакету темы запрещено обращаться к `.brand-mark`,
  `[data-app-mark]` и `agent-hub-mark`; реестр отклонит такой пакет. Полный
  контракт и карта платформенных вариантов находятся в
  [`BRANDING.md`](../../../BRANDING.md).
- Верхняя desktop-оболочка тоже принадлежит Hub: шапка, переключатель разделов,
  кнопка настроек, верхние границы Workspace/чата и карточки Streams сохраняют
  общие положение, прямоугольную форму и размеры. Тема меняет материал через
  документированные `--shell-*` токены и может оформлять значки и типографику,
  но не должна принудительно переопределять эти элементы через `!important`;
  реестр отклонит такой CSS. Это не относится к содержимому чата, списку задач
  и мобильной компоновке. Явно утверждённая тема с собственной цельной
  desktop-композицией должна объявить `"shellLayout": "custom"`; без этого
  opt-in реестр продолжает отклонять принудительные shell-overrides.
- В CSS используйте относительные URL (`url("./image.webp")`), если изображение
  применяется в том же CSS-файле темы. Если URL входит в custom property,
  которую читает общий `styles.css`, объявите файл в `assets` и используйте
  `var(--<id>-<asset>-asset, url("./image.webp"))`: точный URL подставит общий
  каталог, включая VS Code webview.
- Допустимы CSS, JS, HTML, PNG, JPEG, WebP, GIF, SVG и AVIF. Не кладите в папку
  исполняемые или служебные файлы.
- Реестр отклоняет выход из папки через `..`, несовпадение id, отсутствующие
  объявленные файлы, повторяющиеся `order` и id фонов, неизвестные расширения,
  неизвестные встроенные частицы и попытки изменить фирменный знак. Ошибка
  останавливает запуск или сборку, чтобы неполная тема не публиковалась молча.
- `theme.json` и этот README не раздаются локальным сервером; растровые ресурсы
  получают immutable-кэш, CSS/JS/HTML — `no-store`.

## Проверка

Из каталога `Utilities/AgentHub` выполните:

```powershell
node --test theme-registry.test.mjs mini-app-server.test.mjs
node --test VSCodeExtension/render.test.js
npm run worker:build
```

Первый тест создаёт временную тему, которой нет ни в одном списке исходного
кода, и проверяет её автоматическое обнаружение, раздачу ресурсов и внедрение в
HTML. Перед публикацией используйте полный `npm test`.

# Матрица CLI-приёмки Agent Hub

`npm run test:e2e` запускает настоящий `agent-hub-server.mjs` в изолированном временном каталоге. Вместо внешних сервисов используются локальные HTTP Telegram Bot API, Codex App Server и Claude CLI из `e2e`. Рабочие токены, `config.json`, пользовательские треды, папка `data` и производственные логи не читаются и не изменяются.

## Покрытые сценарии

| Область | Проверка |
|---|---|
| Запуск | первичное создание Codex-треда, `/start`, сохранение `state.json` |
| Каталог задач | `/tasks`, порядок кнопок, новая задача перед архивированием |
| Локальная синхронизация | сохранение каталога, истории, статуса, `turnId` и владельца текущего turn (`VSCode App Server`/`Agent Hub Server`/`Codex Desktop App`/`Codex CLI`/неизвестный external) без наследования исторического `originator`; классификация живого дерева процессов rollout с безопасным `EXT` при неоднозначности; ограничение кэша без вытеснения активных задач; фоновое observer-подключение реального внешнего fake-VSC-хода по `client_id` без самопроизвольной progress-карточки; показ по запросу; протухание фантомного running; отсутствие записи неизменившихся poll-снимков |
| Выбор | переход на другую задачу, повторный выбор текущей, восстановление `threadId` |
| Настройки задачи | модель Codex, reasoning, Plan/Work, закреплённое название |
| Обычный ход | запуск, progress, токены, task-aware diff, единая финальная карточка с полной шапкой, удаление заменённой progress-карточки только после доставки финала, очистка active run; владелец HUB-run остаётся `Agent Hub Server` после фонового poll и восстановления состояния |
| Подтверждения | запрос команды и одноразовое UUID-разрешение, привязанное к точному Telegram-сообщению; legacy-счётчики не принимаются; безопасная MCP-форма автоматически принимается в авто-режиме без лишнего сообщения пользователю |
| Конфликт сообщений | запрет второго turn в занятом thread, указание владельца App Server, `Показать текущий ход`, `Отменить`, `Поставить в очередь`, `Отправить в новую задачу` |
| Параллельность | два одновременно активных хода, переключение между ними обоими типами кнопки с глазами, независимая отмена и восстановление обоих ходов после рестарта процесса; параллельные VS Code turns одного треда сохраняют отдельные rollout-сообщения по `turn_id`; финал восстановленного управляемого хода сохраняет подпись `📊 За задачу` |
| Очередь | запуск сохранённого сообщения после завершения/отмены занятого хода |
| Пакет пересылок | первая пересылка не запускает ход; видимые и скрытые авторы, следующие реплики и комментарий пользователя сохраняются одним черновиком в `state.json`, переживают рестарт процесса, а кнопка отправки создаёт ровно один turn в исходном порядке |
| Архив | запрет при активном ходе, успешная архивация после завершения и отказ устаревшей кнопке меню воздействовать на позднее выбранную задачу |
| Просмотр | новые кнопки несут `provider + threadId`, переживают удаление bindings и подключают live-ход; старые `show-message`/`show-last-message` совместимы, а без активного хода показывается последний ответ |
| История | self-contained кнопка `Показать ещё` перестраивает представление с последовательным увеличением числа пар `1 → 2 → 3` |
| Отмена | `/cancel` относится только к выбранной задаче; неудачный interrupt внешнего хода сохраняет observer и блокировку второго turn |
| Доставка | HTTP 500, durable-before-send outbox для финала, повторная отправка progress и финала; групповой порядок частей, обход delayed-группы независимыми сообщениями, карантин повреждённой записи, вытеснение старого progress, конкурентная append-only запись и безопасная компактация bindings; сбой `getUpdates`, ограниченный backoff и последующее восстановление polling; фоновый observer не отправляет полный финал без явных «глазок», а восстановленный observer не повторяет накопленный ответ |
| Состояние Windows | повтор атомарной записи при `EPERM`/`EACCES`/`EBUSY` |
| Codex recovery | падение App Server во время хода, переподключение и доставка восстановленного финала; откат незавершённого turn и безопасное продолжение после потерянного MCP-запроса в авто-режиме |
| Рестарт | системный single-instance lock, восстановление активного run, фактического владельца и постоянного курсора terminal-аудита после процесса, штатный `/restart` с сохранением Telegram offset и обновлением карточки; соседний update из уже полученного пакета обрабатывается новой копией ровно один раз; временная ошибка `thread/resume` не создаёт новый выбранный тред поверх сохранённого активного хода; отдельный Windows integration-тест проходит настоящий путь WMI → launcher → новый `bot.lock`, причём прежняя копия не принимает запуск за успешный до появления lock |
| Нагрузка | управляемый Telegram-ход использует поток App Server; периодическое наблюдение читает только metadata и ограниченный инкрементальный хвост rollout вместо полной истории; чтение истории и live-снимка одного треда объединяется; короткий внешний VSCode-ход, целиком прошедший между опросами, сохраняет финал для истории, но не отправляет его только из-за выбора задачи; искусственно задержанный на три секунды Claude `/usage` внутри `/status` не задерживает следующий `/cancel` |
| Медиа | медленная загрузка изображения не блокирует команды и переключение; начатый после загрузки ход остаётся привязан к исходной задаче, модели и режиму; два быстрых изображения проходят FIFO-очередь ровно по одному разу; принятая работа сохраняется до Telegram offset, переживает жёсткое завершение бота во время загрузки, завершается после старта новой копии и очищает журнал; пересланный Telegram-альбом из трёх изображений попадает в один сохраняемый пакет, до явной отправки не создаёт ни хода, ни очереди сообщений и стартует одним входом со всеми файлами |
| Статус | отправка медиа-карточки `/status`; четыре кнопки: активные первыми, затем недавние по времени активности |
| Агенты | переключение Codex → Claude → Codex и полноценный ход fake Claude CLI |
| Проекты | переключение между двумя разрешёнными проектами с отдельными контекстами |

## Матрица параллельности Claude

`agent-hub-server.claude.e2e.test.mjs` запускает отдельный экземпляр сервера с `provider: "claude"`, подставным Claude CLI и изолированным домашним каталогом, поэтому реальные сессии `~/.claude/projects` не читаются.

| Область | Проверка |
|---|---|
| Параллельность | две одновременно активные задачи Claude с разными сессиями и собственными файлами вывода |
| Конфликт сообщений | занятая задача Claude предлагает отложенное сообщение и запуск в новой задаче |
| Выбор и просмотр | `/tasks` показывает обе живые задачи; self-contained `Показать сообщение` работает после удаления bindings, переключение не останавливает ни одну задачу |
| Рабочий каталог | сессия Claude, созданная во вложенной папке разрешённого проекта, возобновляется из своего исходного `cwd`; подставной CLI отклоняет тот же `--resume` из корня проекта |
| Изображения | Desktop отправляет PNG в существующую Claude-сессию; prompt остаётся отдельным аргументом после многозначного `--add-dir`, попадает в transcript и завершается нормальным ответом без ошибки `deferred tool marker` |
| Отмена | `/cancel` завершает только выбранную задачу Claude и останавливает настоящий дочерний процесс CLI; незавершённый transcript отменённого управляемого хода не воскресает как внешний observer |
| Рестарт | процесс CLI переживает жёсткое завершение бота и штатный `/restart`, ход подключается заново и доставляет финальный ответ; сообщение о прерывании не отправляется, а `/restart` не откладывается |
| Неопределённая активность | брошенный незавершённый transcript выбирается как задача, не считается выполняющимся, не запускает новый ход автоматически и требует отдельной кнопки явного продолжения |
| Гонки наблюдения | переключение задачи или запуск управляемого хода во время чтения snapshot не создают observer для прежнего thread/session |
| Уборка | осиротевшие `data/claude-runs/*` удаляются при старте, файлы восстановленных активных ходов сохраняются |

## Команды

```powershell
npm run check
npm test
npm run test:e2e
npm run test:all
```

`npm run check` одним процессом разбирает все `.mjs` без исполнения. `npm test` — быстрые unit/integration-тесты. `npm run test:e2e` — процессная CLI-приёмка. `npm run test:all` последовательно выполняет синтаксическую проверку, оба набора тестов и является основной командой перед выпуском. На Windows общий стенд масштабирует только технические таймауты ожидания вдвое, сохраняя отдельные проверки фактической отзывчивости; значение можно явно задать через `TELEGRAM_E2E_TIMEOUT_MULTIPLIER`. При таймауте стенд печатает последние Telegram API-вызовы, чтобы отличить задержку процесса от ошибки маршрутизации.

В `npm test` также входит изолированная приёмка control plane: публикация двух runtime-релизов, атомарное переключение и откат `current/previous`, отсечение тестов и локальных секретов из release, явная миграция config/data, ACL конфигурации, ожидание завершения активных ходов перед cutover и локальный IPC, разрешающий только отправку сообщений и изображений без передачи Telegram-токена. Негативные проверки отклоняют чужой chat, файл вне проектов и смешанное окружение Codex/Claude; резервная файловая очередь проверяется отдельно от named pipe. Контроллер polling отдельно доказывает, что полный ошибочный update попадает в DLQ до продвижения offset, а ошибка записи state откатывает offset в памяти.

## Границы

Headless-стенд проверяет протоколы, состояние и маршрутизацию без управления компьютером. Он не оценивает визуальный рендеринг карточек конкретной версией мобильного/настольного Telegram, качество распознавания речи и звучание TTS. Формирование соответствующих Bot API-запросов покрыто модульными тестами; визуальная оценка остаётся отдельным необязательным smoke-тестом.

# Отдельный экран хода выпуска

Локальный read-only веб-интерфейс для существующего release pipeline. Не зависит
от работающего интерфейса или HTTP backend AgentHub; читает сохранённые
`runner.json`, `publication-status.json` и лог. Ничего не запускает, не повторяет,
не останавливает и не записывает в runtime. Готовность Hub не подменяет итог выпуска.

Из исходников с установленным Node.js, без npm/build/dependencies:

```powershell
node release-progress/server.mjs --runtime-root <runtime-root> --operation <original-operation-id> --title "Выпуск 2.0.0"
```

Команда печатает локальный URL. По умолчанию ОС выбирает свободный порт; при
необходимости `--port <port>`. Слушает только `127.0.0.1`. Открывай напечатанный
адрес буквально: Host/Origin проверяются, CORS и управление выпуском отсутствуют.
Закрытие страницы не останавливает ни монитор, ни выпуск. `Ctrl+C` в терминале
останавливает только процесс этого монитора. Автозапуск и установка в runtime
не добавляются.

Экран показывает все записанные стадии с описаниями и длительностями, результаты
тестов, их исходные названия, русскую область/пояснение, записанные ошибки и лог.
Пояснения по области — навигация, а не перевод или новое утверждение о покрытии;
точное условие остаётся в оригинальном названии. Поиск и фильтры работают по всем
прочитанным результатам. Таблица дорисовывает по 100 строк; «Показать ещё» не
отбрасывает результаты. Окно лога показывает последние 200 строк, полный файл
доступен по ссылке. Нет выдуманного процента или ETA.

Состояние обновляется раз в две секунды; файл лога читается потоково только с
последней позиции, в том числе при разрыве UTF-8 символа между записями. Смена
поколения/файла или укорочение лога сбрасывают проекцию. Ошибка чтения сохраняет
последние данные с явным сообщением. Давность лога не объявляет процесс зависшим
или завершённым. Название текущего незавершённого теста pipeline не публикует:
поэтому экран честно показывает последний завершённый тест.

Нужен существующий `data/release-operation-executions` в заданном runtime-root.
Выбирается самое позднее сохранённое поколение **только заданной операции**.
Пути HTTP запроса не используются как пути файлов; logFile допускается только
внутри выбранного execution root после физического разрешения пути. Локальный
пользователь видит свой исходный лог; не публикуй этот порт через прокси или туннель.
Оригинальный publish stage — имя стадии, а не доказательство Done.

Адресные проверки:

```powershell
node --test tests/interfaces/release-progress.test.mjs
```

Они проверяют потоковый разбор/повторную печать ошибок, новое поколение/укорочение
лога, read-only HTTP, literal unsafe text и отказы чужих путей/Host/Origin. Рендер
и пользовательские взаимодействия проверяются отдельно в браузере.

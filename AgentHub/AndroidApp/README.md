# Agent Hub Mobile

Android-клиент использует тот же внутренний Web App, что Telegram Mini App, но
не зависит от Telegram. Приложение открывает публичный HTTPS Agent Hub через
Worker либо прямой шлюз и авторизуется отдельным ключом устройства.

Launcher использует единый знак Agent Hub из трёх цветных стеклянных лент на
тёмной подложке, сохраняя читаемость под системной маской значка.

Системный выбор файлов поддерживает одно или несколько изображений. При
выделении текста ответа Android сохраняет штатные действия `Копировать`,
`Поделиться` и `Поиск` и добавляет к ним `Цитировать`; комментарий к каждой
добавленной цитате вводится в собственной карточке над композером.

Компонент включается командой:

```powershell
python Utilities/AgentHub/install.py --enable-component android-app
```

Требуются Android 8.0 / API 26 или новее, публичный HTTPS-адрес с действующим
сертификатом и однократное сопряжение телефона. Адрес может быть субдоменом
общего `darksanctuary.ru` либо собственным доменом. Общий шлюз сейчас находится
на домашнем компьютере владельца домена и доступен, пока этот компьютер включён;
после покупки сервера шлюз можно перенести туда. Для собственного домена нужны
управление DNS, HTTPS и маршрут до Hub, зато зависимости от общего домена нет.

## Защита подключения

- закрытый ключ P-256 создаётся в Android Keystore и не экспортируется;
- HUB выдаёт одноразовый 20-символьный код сопряжения на 10 минут; запросить код
  можно локально или из уже доверенного браузера, но не из Android-клиента;
- телефон подписывает серверный challenge вместе с origin настроенного Hub
  (`agent-hub-device-session-v2`), после чего получает сессию на 12 часов;
  подпись, сделанная для другого адреса, не принимается;
- сессия хранится в HttpOnly-cookie WebView и недоступна скриптам страницы;
- список устройств, последний доступ и отзыв находятся в общих настройках HUB;
- отзыв немедленно удаляет все активные сессии устройства; если Worker в этот
  момент недоступен, отзыв всё равно считается выполненным и до-реплицируется;
- Telegram-токен, Worker sync secret и локальные пути на телефон не передаются;
- разрешён только HTTPS, ошибки сертификата не обходятся.

Ключ хранится по рекомендациям [Android Keystore](https://developer.android.com/privacy-and-security/keystore),
а Worker проверяет ECDSA P-256 через [Web Crypto](https://developers.cloudflare.com/workers/runtime-apis/web-crypto/).

## Сборка

Требуются JDK 17, Android SDK API 36 и Gradle 8.13. Версии Android Gradle Plugin
и Gradle закреплены в проекте, wrapper содержит SHA-256 официального дистрибутива.

```powershell
pwsh -NoProfile -File AndroidApp/build.ps1 -HubUrl https://hub.example.com -ArtifactVersion <frozen-public-version+build.N>
```

Debug APK создаётся в `AndroidApp/app/build/outputs/apk/debug/app-debug.apk`, а
копия для первой ручной установки — в `AndroidApp/dist/AgentHub-Mobile.apk`.
Та же сборка атомарно публикуется как `assets/mobile/AgentHub-Mobile.apk` вместе
с `update.json` (versionCode, versionName, размер и SHA-256). Эти генерируемые
файлы не хранятся в Git, но входят в следующий runtime-релиз Agent Hub. Если
используется SemVer, `build.ps1` требует `-ArtifactVersion` из существующего
release owner: `versionName` равен публичной версии (например, `2.0.0`), а
`versionCode` — тому же frozen N. Explicit code/name и фактическая Gradle metadata
должны точно совпасть. Повтор сборки не выделяет новый code. Историческая
calendar-сборка сохраняет прежний UTC epoch-minute/date режим только для старых
источников; новые semantic источники без frozen identity отказываются.
Обновление требует увеличения code и неубывания SemVer, включая beta/rc→stable.
Распознанная календарная версия может перейти на major 2 или выше; неизвестная
версия либо downgrade не разрешают установку. Signer, package ID, Keystore,
сессии и enrollment сохраняют существующие владельцы; uninstall/clear не нужны.
Без `HubUrl` адрес можно ввести при первом запуске. Личные URL, ключи телефона и
записи доверенных устройств не хранятся в Git.

### Переход на подпись v2

Hub принимает только `agent-hub-device-session-v2`. Установленный APK предыдущей
версии подписывает challenge без origin, поэтому после обновления Hub его нужно
пересобрать и переустановить — повторное сопряжение старым APK не поможет. Если
телефон требуется временно оставить на старой сборке, запустите Hub с
`AGENT_HUB_LEGACY_DEVICE_SESSIONS=1` (для Worker — переменная
`ALLOW_LEGACY_DEVICE_SESSIONS=1`). Это возвращает приём подписи без origin и
снимает защиту от ретрансляции, поэтому флаг снимают сразу после установки APK.

## Обновление

После авторизации, при возвращении в приложение и после обнаружения нового
экземпляра HUB приложение запрашивает manifest у того же настроенного HTTPS Hub
(не чаще одного раза в пять минут без явного события рестарта). Более новая
версия скачивается в закрытый кэш только с того же origin; redirect запрещён,
размер и SHA-256 проверяются до открытия APK, а Android дополнительно требует ту
же подпись установленного пакета.

На Android 12+ проверенный APK передаётся `PackageInstaller` с запросом установки
без участия пользователя. Android разрешает это не на каждом устройстве и не
при каждом способе первой установки. Если требуется действие, приложение само
открывает штатное системное подтверждение; оно не обходится. На Android 8–11
после загрузки показывается окно «Обновление Agent Hub» с кнопками «Установить»
и «Позже». Разрешение «Установка неизвестных приложений» может потребоваться
один раз для Agent Hub.

## Добавление телефона

1. Откройте общие настройки Agent Hub.
2. В разделе «Доверенные устройства» нажмите «Добавить устройство».
3. Установите APK, укажите HTTPS-адрес и одноразовый код.
4. После сопряжения телефон появится в списке. Кнопка «Отозвать» немедленно
   блокирует дальнейший доступ этого устройства.
